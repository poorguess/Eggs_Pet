# 孵蛋养成 MVP 设计交流稿

日期：2026-09-07

> 说明：这份中文版仅用于团队沟通与协作理解。实际开发以英文版 `2026_09_07_egg_pet_mvp_design.md` 为准。

## 概述

本 MVP 是一款温和治愈的 2D 手绘风手机横屏游戏，核心围绕孵蛋与养成展开。玩家在漂浮小岛上照顾一颗普通蛋，帮助它孵化成第一只宠物“壳壳布丁”，并通过场景中的小互动逐渐建立亲密关系。

养成循环是主玩法。小游戏只是可选的娱乐内容，在 MVP 阶段不产出资源、不推进成长、不写入记忆，也不改变核心状态。

## 目标

- 做出完整的“蛋到宠物”养成闭环。
- 让主岛界面保持干净、温暖、可互动，不使用常驻照顾按钮。
- 用宠物动作、表情和场景反馈替代管理感很重的 UI。
- 系统结构预留未来多蛋种、多物种扩展，但 MVP 只实现一种蛋和一种宠物。
- 加入一个轻量割草类小游戏作为可选娱乐。
- 所有负面状态都保持轻微、可恢复。

## 非目标

- 不做商店、金币、材料或道具体系。
- 不实际制作多物种内容，只预留数据结构。
- 不做复杂肉鸽构筑系统。
- 不做死亡、离家出走、永久失败或强惩罚。
- 小游戏不提供奖励，只在结束后播放胜利或失败动画。

## 平台与表现

最终目标平台是手机横屏。电脑仅作为开发和调试环境，可以临时使用鼠标和键盘模拟操作。

美术风格为 2D 手绘可爱风。主场景是一个干净的漂浮小岛，视觉重点应放在蛋、壳壳布丁和岛上的可互动物件上，而不是界面按钮。

## 核心体验

玩家从漂浮小岛上的一颗普通蛋开始。蛋会随着现实时间和玩家主动照顾逐渐变化。玩家通过蛋或宠物的动作、表情和场景状态判断需求，然后点击岛上的物件进行照顾。

当蛋达到可孵化状态时，游戏播放一段短孵化表现，并出现壳壳布丁。孵化后，壳壳布丁继续生活在同一座小岛上，并对食物、温度、清洁、玩具和陪伴产生反馈。

## 第一只宠物概念

壳壳布丁是一只柔软、奇怪、亲近人的小生物。它的身体像一团会呼吸的布丁，头上顶着裂开的蛋壳帽。移动时会软软地挤压和弹跳。开心时会扭动或顶着蛋壳转圈；不安时会缩进壳下，只露出眼睛偷看。

MVP 使用混合动画策略：

- 程序动画：待机呼吸、轻晃、弹跳、躲壳、快速反应、胜利、失败。
- 序列帧动画：后续用于高价值表现，比如孵化、被摸摸、睡觉、特殊亲密动作。

游戏逻辑只通过动作名调用表现。这样后续即使用视频转序列帧替换关键动作，也不需要重写养成逻辑。

## 照顾模型

MVP 追踪 4 个核心状态，范围均为 `0-100`：

- 温度
- 饱腹
- 清洁
- 心情

舒适区大约是 `60-100`。低于 `40` 时，蛋或宠物应明显表达需求；低于 `20` 时，出现轻微负面表现，例如躲起来、动作变慢、身上变脏、回应变少。

游戏不做死亡、永久失败或不可逆伤害。低状态的作用是邀请玩家照顾，而不是惩罚玩家。

## 场景物件交互

主岛不使用常驻的右侧或底部照顾工具栏。照顾行为主要通过场景物件和宠物反馈完成。

MVP 需要包含以下可互动物件：

- 蛋窝或宠物休息区。
- 食物盆：用于放置食物。放入食物后，壳壳布丁可以自主靠近并吃掉。
- 暖灯或类似加热物件：用于调节温度。
- 清洁物件：例如小水盆或毛巾。
- 玩具或陪伴物件。
- 小游戏 Hub 入口：需要在主岛上可见，或以轻量 UI 形式呈现。

临时 UI 只在交互时出现，例如点击食物盆后弹出食物选择，或点击小游戏入口后弹出小游戏选择。默认画面应尽量保持干净。

## 离线推进

游戏保存上次存档时间。再次进入游戏时，根据经过时间计算温和的离线变化：

- 孵化进度缓慢增加。
- 饱腹、清洁和心情轻微下降，但有安全下限。
- 温度根据环境和暖灯状态缓慢偏移。
- 长时间离线可能触发轻微事件表现，例如小岛有点乱，或壳壳布丁缩在壳下等玩家回来。

离线衰减必须有安全下限，不能制造强惩罚。

## 成长与亲密

蛋阶段的成长以孵化进度 `0-100` 表示。达到 `100` 后进入可孵化状态。孵化应由玩家触发，或通过清晰表现引导玩家触发，不应突然自动切换。

孵化后开始计算亲密度。MVP 亲密等级分为 3 级：

- 陌生
- 安心
- 亲近

照顾行为和舒适状态会缓慢增加亲密度。第一版优先做动作反馈。每个亲密等级解锁或强化一个小动作，例如主动靠近、开心摇晃、被摸摸时放松眯眼。

文字和自主行为可以轻量存在，但 MVP 的优先级是看得见的动画反馈。

## 小游戏结构

项目未来应支持多个小游戏，但 MVP 只实现“泡泡割草”。

小游戏结构为：

- 小游戏 Hub：从主岛上的可见入口打开。
- 泡泡割草：第一版唯一可玩小游戏。
- 未来小游戏：之后通过同一个 Hub 增加。

主养成系统不需要知道小游戏内部规则。

## 泡泡割草 MVP

泡泡割草是一个轻量割草类小游戏：

- 玩家只控制壳壳布丁移动。
- 壳壳布丁自动向最近敌人发射泡泡子弹。
- 敌人会靠近玩家。
- 单局持续较短时间，或用简单胜负条件结束。
- 结束后返回主岛，并播放胜利或失败动画。

MVP 阶段，泡泡割草不提供金币、材料、亲密度、心情、记忆、孵化进度或任何养成奖励。

## 存档数据

主存档建议包含：

- 当前阶段：`egg` 或 `pet`。
- 蛋种：`common_egg`。
- 孵化后的宠物物种：`shell_pudding`。
- 4 个核心状态值。
- 孵化进度和可孵化标记。
- 亲密点数和亲密等级。
- 已解锁动作名。
- 场景物件状态，例如食物盆内容、暖灯开关状态。
- 最后保存时间。

可以预留记忆记录结构，但 MVP 的小游戏不写入记忆。

## 建议 Godot 场景结构

- `main_island.tscn`：漂浮小岛养成主场景和主流程。
- `egg_view.tscn`：蛋阶段表现和动作播放。
- `pet_view.tscn`：壳壳布丁表现和宠物阶段动作播放。
- `interactable_item.tscn`：可互动物件基类。
- `food_bowl.tscn`：食物放置交互。
- `warm_lamp.tscn`：保温交互。
- `clean_tool.tscn`：清洁交互。
- `toy.tscn`：陪伴交互。
- `minigame_hub.tscn`：小游戏选择 UI。
- `bubble_survivor.tscn`：第一个小游戏。

## 建议脚本结构

- `care_state.gd`：状态范围、状态变化、舒适区判断和数值限制。
- `growth_state.gd`：孵化进度、可孵化状态、亲密度和动作解锁。
- `save_data.gd`：存档资源或可序列化数据结构。
- `save_service.gd`：保存、读取和离线推进。
- `creature_animator.gd`：通过动作名播放程序动画和未来序列帧动画。
- `interactable_item.gd`：通用交互行为。
- `minigame_hub.gd`：小游戏选择与场景切换。
- `bubble_survivor_controller.gd`：泡泡割草内部规则。

## 实现阶段

### 阶段 1：主岛原型

制作手机横屏漂浮小岛原型，使用占位美术即可。需要包含蛋窝、食物盆、暖灯、清洁物件、玩具或陪伴物件，以及一个可见的小游戏 Hub 入口。

即使视觉是临时的，交互也应真实可用。

### 阶段 2：照顾与孵化闭环

实现照顾状态、成长状态、存档数据、保存与读取、离线推进、可孵化状态和孵化切换。

### 阶段 3：壳壳布丁

实现宠物阶段、亲密等级、动作解锁和 `creature_animator.gd` 动作名系统。MVP 使用程序动画表现反馈。

### 阶段 4：泡泡割草

实现小游戏 Hub、泡泡割草、玩家移动、自动泡泡攻击、简单敌人、胜负条件，以及返回主岛后的结果动画。

## 验证要点

MVP 验证需要确认：

- 核心状态数值不会越界。
- 离线推进是温和的，不会产生强惩罚。
- 蛋可以稳定进入可孵化状态，并孵化成壳壳布丁。
- 存档读写后，当前阶段、状态、孵化进度、亲密度和物件状态保持一致。
- 主岛在手机横屏布局下保持干净且可交互。
- 小游戏 Hub 入口在主岛上可见，或能被明确发现。
- 泡泡割草只返回胜利或失败，不改变养成进度或资源。
- 从小游戏返回后，胜利或失败动画能正确播放。
