# 宠物换脸模块补充设计

依据 2026_09_07_egg_pet_mvp_design.md 与本次用户需求。仅扩展外貌，不改变照护、成长、主岛构图和小游戏。

## 数据与跟踪

运行时 `scripts/face/face_track.gd` Resource 保存版本、动画名、序列图路径、行列、帧数、基准帧 0、各帧同序轮廓点以及可见性。坐标为单帧左上角起的像素坐标。轮廓按顺时针、从额头顶端开始，各帧点数和语义一致；支持 4–64 点的简单、以点均值为核的星形轮廓。校验越界、自交、退化和点数不匹配。

轮廓定义可放置五官的区域，不定义眼距或鼻嘴间距。基准轮廓内部生成同心网格，使用均值坐标计算每个顶点在各帧的位置；UV 始终由基准帧及用户平移、缩放、旋转计算。用户只对齐一次，动画沿用相同 UV。贴图随 Sprite2D 的 frame、flip_h/flip_v、offset 和父级变换同步。缺帧在相邻有效关键帧间插值，首尾采用最近帧；隐藏帧不显示五官。无效数据仅停用换脸层并报告错误。

旧三点轨迹无法恢复真实轮廓。插件可显式导入为椭圆草稿并提示校正。主项目默认数据基于当前 character1.png 的每帧面部浅色区域提取，保留来源标记，需要美术最终复核。

## 编辑器插件

`addons/face_track_editor` 只提供开发者轮廓编辑工作台：载入/新建轨迹、选择帧与点、拖动点/整个轮廓、复制前帧、清除帧、显示/隐藏、预览播放、保存校验和旧格式转换。支持已有 SpriteFrames 和规则序列图，保存时引用运行时数据脚本。导出预设明确排除整个插件目录；运行时不引用插件。

## 生图

复用 FaceCamera 和 FaceApi 的拍照/选图、HTTP 上传、超时、取消机制。强制内嵌五官贴图提示词，旧 cfg prompt 不可改变输出协议。仅上传自拍（不需要生成身体）；固定正面排列，保留个人五官差异。透明 RGBA PNG；若上游不支持透明，唯一允许的替代为纯洋红底，客户端按色键清除，包括五官间的独立区域。不得以白色或肤色阈值删除皮肤，以免损坏眼白和嘴部。

客户端校验尺寸、有效非透明内容、透明边界及透明面积；这些是格式检查，不声称自动识别所有皮肤或身体。用户预览是语义验收环节，不合格可重拍/重新生成。没有远端实测时明确记录限制。

## 用户界面与持久化

独立 `scenes/face_customizer.tscn`，从原右下按钮打开。左侧角色第 0 帧静态预览；右侧上传自拍、横纵位移、整体缩放、宽高比例、旋转、重置、应用和取消。保持整张五官贴图内部差异，不增加逐五官拆分系统。使用标准 Control、Slider、Button，兼容鼠标与触摸，横屏布局及滚动面板。

界面以信号请求拍照和应用。拍照前说明上传用途；PC 选图、移动端原相机流程继续使用。生成结果为草稿，应用后才写入 user:// 外貌 JSON 与 PNG。取消、生成失败、保存失败保留旧外貌。外貌存档独立，不触碰照护数值。旧整身 PNG/圆头像继续兼容，应用新五官后切换回序列动画。再次打开可调整已保存五官，不必重新调用模型。

## 验证

Godot headless：轮廓身份映射、平移和形变、缺帧插值、非法轮廓拒绝、抠图保护眼白、空图拒绝、资源保存重载、UI 草稿取消、Sprite 镜像和帧跟随。运行主场景检查解析与运行时错误；离屏渲染检查左预览右面板。导出 PCK 检查插件路径不存在而运行时轨迹可加载。真实相机、真实生成质量和手机触摸须标注实际测试范围。
